# 长期陪伴型 Agent：功能共识

状态：功能头脑风暴的方向参考；于 2026-10-19 进入技术架构讨论，具体功能允许随架构演进调整。

技术讨论约定：本文不代表最终成品或固定交付承诺。设计尽量接近本文描述的体验，最终实现以双方约定的技术架构及其演进结果为准。优先追求简洁设计与可扩展性；由精简内核配合官方扩展承载能力是待探讨的方向，尚未确定具体边界。

已确认的早期架构取舍见 [本机运行与信任型扩展](../adr/0001-local-runtime-and-trusted-extensions.md)；其中允许电脑休眠期间暂停活动，本文关于离线主动联系的描述仍作为后续体验方向。

本文记录功能访谈中使用者逐项确认的需求、可选能力与后续讨论事项。当前仅讨论使用体验和功能，不决定技术选型、实现方式或细粒度行为规则；完整功能方向不等于首版交付范围。

产品定位：首先供使用者本人使用、有稳定身份和自身性格、能够感知当下并主动交流、通过记忆和共同经历持续发展关系的陪伴者，同时允许通过扩展增加实际做事的能力。

## 已确认

### 使用者与关系

- 首先供使用者本人使用。
- 陪伴者更像一个有自己性格的朋友，关系可以慢慢发展。
- 希望始终是同一个陪伴者；更换渠道、形象或模型服务后，记忆仍然延续。
- 陪伴是核心，也希望通过扩展增加实际做事的能力。
- 初始设定少量稳定的性格特征，相处习惯可以逐渐形成；陪伴者可以有不同观点和自己的偏好，变化应能从共同经历中理解。
- 具体措辞、回应方式以及如何表达好奇等交给人设和模型发挥，不预先规定固定话术或强制的对话流程。

### 角色卡

- 支持人设编辑、保存，以及角色卡导入导出；这是辅助管理功能，不作为产品重点。
- 修改人设不意味着清空已经积累的记忆。
- 具体字段和格式兼容性留待后续设计。

### 屏幕感知

- 希望屏幕感知可以长期开启。
- 使用者可以随时暂停屏幕感知。
- 提供排除应用或内容范围的能力。
- 允许将感知到的屏幕内容转化为长期记忆，不要求保留全部看到的内容。
- 暂停屏幕感知后仍可聊天，只是不再获得新的屏幕信息。

### 主动联系

- 优先期待下班后主动询问今天过得怎么样。
- 期待陪伴者看到使用者正在学习时表达好奇，或者聊上几句。
- 很久没有回应时，希望陪伴者可以隔一段时间再来联系。
- 一次主动联系未获回应后，先安静一段时间；允许当晚晚些时候再主动来一次，不要求一定等到次日。
- 下班后可以直接问候今天过得怎么样，但不将其规定为固定话术或必须遵循的交流流程。
- 允许在使用者离开电脑、桌面软件关闭或电脑休眠时，通过其他渠道主动联系。

### 长期记忆

- 可记住生活习惯、喜好、相处偏好、明确要求记住的事情、有意义的经历、共同经历，以及交流中值得保留的小细节。
- 不要求记住每句话。
- 使用者可以查看、纠正记忆，或要求遗忘。
- 记忆可以自然体现在回应和相处方式中。
- 希望可以更换今后的记忆方式，并尽量延续已经积累的记忆；具体保留范围、迁移及备份恢复需求留到记忆系统设计时讨论。

### 做梦

- 空闲时回顾交流、整理已有记忆，包括重复或矛盾的信息，并更新对使用者的理解。
- 当前只做整理，不需要虚构梦境。
- 后台自然进行，保留可选查看的整理记录，不要求使用者阅读，也不要求每次主动汇报。

### 扩展与管理

- 提供统一的扩展管理入口和管理面板。
- 能查看已安装扩展及其作用、影响的行为，调整设置，并单独启用、停用或卸载。
- 管理面板可以在桌面软件或外置平台中提供，具体位置与技术暂不决定。
- 扩展候选范围包括新增做事能力、调整行为或人设指令、发起交流，以及调整上下文和记忆方式；具体接口留待技术阶段。
- 本轮确认可通过扩展增加实际做事的能力，不预先要求内置搜索、笔记、提醒、文件或软件操作等一整套工具；具体工具后续按需开发。

### 统一管理面板

- 提供统一管理入口，日常交流保持轻便，设置与查看记录时再打开管理面板。
- 管理人设、形象、模型、渠道和扩展。
- 查看、纠正和删除记忆。
- 查看做梦整理记录和行为泳道。
- 查看运行状态，暂停主动联系或屏幕感知。
- 页面布局和面板所在位置留待后续设计。

### 模型选择

- 支持配置多个模型服务，选择和切换当前使用的模型。
- 切换模型不改变陪伴者身份，记忆应延续。
- 按不同活动分别选择模型列为可选能力，具体调用方式留待技术阶段。

### 行为泳道

- 提供只读过程总览，也能展开查看详细记录。
- 展示实际记录下来的陪伴者与扩展行为，覆盖已记录的模型交互、工具输入及结果、扩展活动和失败信息等。
- 以实际保存的行为记录为依据回看过程，不将该视图理解为另行生成的过程叙述。
- 使用者提出以数据库中记录的行为为展示依据；数据库与记录方式不在本轮决定。

### 桌面形象

- 支持 Live2D 卡通形象，常驻桌面，可移动、隐藏和更换形象。
- 交流时具备基础表情和动作表现。
- 触碰互动留待以后考虑。

### 交流形式

- 支持文字交流；图片、语音消息和连续语音交流进入候选清单，可共存，不要求二选一，也不要求每个渠道具备全部形式。
- 不同渠道延续同一个陪伴者的身份与记忆。
- 希望跨渠道能够直接接续话题，界面不必展示全部渠道的历史记录。
- 若无缝接续使实现过于复杂，可以接受按独立对话批次交流，以技术设计简单可靠为优先；具体取舍留到技术设计时决定。

## 可选能力

- 图片交流：主动发送图片或截图供陪伴者理解和讨论。
- 语音消息：发送语音消息、听取语音回复。
- 连续语音交流：像通话一样持续交谈。
- 按不同活动分别选择模型，例如聊天与后台整理分别选择。
- 网页交流入口：作为可选扩展渠道，当前不要求所有交流入口齐备。
- 文件阅读：后续按实际需要决定，当前未确认为必需功能。
